### API and error semantics

- `parse_amount_text(value: str) -> Cents` accepts ASCII digits with no decimal point or one/two fractional digits, left-padding a single fractional digit, and returns a plain integer using `whole * 100 + fraction` arithmetic.
- It rejects blank or whitespace input, malformed forms, signs, surrounding whitespace, grouping separators, exponent notation, zero, negatives, and more than two decimal places. It performs no floating-point arithmetic and converts parser failures to the stable domain boundary.
- Invalid input raises `InvalidAmountError`, a `DomainError` carrying `code == "invalid_amount"` and the API-compatible `error_code` property. The default message explicitly states the two-decimal-place limit.
- `ErrorCode` and exported string constants define `invalid_amount`, `no_beneficiaries`, `no_participants`, `invalid_participant_reference`, and `contribution_mismatch` for subsequent domain tasks. No split, balance, settlement, application, auth, persistence, API, or client behavior was added.
